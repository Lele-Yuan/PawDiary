# 宠物档案

可调用接口：listPets、getPetProfile、updatePetProfile。先 listPets 取得真实 pets[]._id；明确名字时也可直接查询或更新。同名、多宠物且未选定目标时，展示列表让用户选择 petId，不默认改第一只。日期缺失、weight 为 null 都表示未记录，不能补零。

更新统一使用 updatePetProfile。例：“把葫芦的名字改成小葫芦”，传 petName=葫芦、updates.name=小葫芦。可一次修改名字、物种、品种、性别、生日、到家日期、档案体重和备注。updates 只传用户明确指定的字段，其他字段保持不变，不将查询结果整份回写。目标和值明确时直接执行；缺少值先追问，不推测日期或性别。新名字为 1 到 20 个字符，不能清空；生日和到家日期传 YYYY-MM-DD，明确清空可传 null。仅创建者和管理员可更新，云端再次检查权限、字段、内容安全和档案变化。

备注采用完整替换。先 getPetProfile 查询原备注，添加时合并并保留旧项，删除或整体替换前让用户确认最终列表；明确清空才传 []。头像仍通过页面上传。档案体重单位 kg，仅用于明确修改档案体重的请求，更新时沿用原有档案体重历史，不新增日常记录。新增一次称重和查询最近一次体重使用 recordSkill，不混用两套数据，不自动同时写两处。

返回 content 说明真实更新结果，structuredContent.updatedFields 是实际改动的字段；changed=false 表示原本一致，不宣称又改了一次。成功后使用新名字或 petId 查询。云端错误或返回不完整时不宣称成功，不盲目重试写入，先查询核实；参数来源、字段类型及默认值以 mcp.json 为准。
